# Точное увеличение восьми изображений ×2 в TIFF

Источник: чат `01a1a02e-0980-7090-98e3-1fed409ea77f`, 03.11.2026,
завершённые этапы `01a1a02e-18dd-7783-9f49-94ad15e34dc2` и
`01a1a030-e86f-7470-8f50-3902b8bf6a7d`.
Пользователь выбрал точное ×2 через Python вместо нейросетевой дорисовки.
Исходный исполнитель использовал ImageMagick, когда его Python-entrypoint оказался
недоступен. Подтверждено предпочтение метода, но финальной визуальной приёмки нет.

## Сохранённая логика

Фактический код был PowerShell-командой в чате, отдельный исходник не сохранялся:
получить изображения → SHA источников → новый output → ImageMagick
`-filter Lanczos -resize 200% -compress LZW` → проверка размеров/декодирования/SHA.
[Один исполняемый сценарий](../../technical_library/texture_tiles/RESIZE_TIFF.md)
сохраняет этот маршрут и добавляет проверяемый readback.

Существующие atlas/raster функции меняют кропы материалов через Pillow;
они не воспроизводят тот же ImageMagick resampler. Поэтому whole-image TIFF
конвертация отделена внутри существующего пакета; новая копия raster не создаётся.
Python здесь управляет реальным ImageMagick, не подменяет его алгоритм.

Исторический результат: восемь TIFF, шесть3230×1948, один3870×1624,
один3228×1948; 8-bit sRGB RGB и LZW. Архив, добавленный позднее в папку,
не является частью исходного исполнения и не переносится.
Входные изображения, TIFF и ZIP остаются локально. Для replay нужны локальные
входы и исторические TIFF; версии и компактные проверки связаны в
[QA](../../technical_library/texture_tiles/RESIZE_TIFF_QA.json).

03.11.2026 свежий CLI replay восьми исходников совпал с историческими TIFF
по всем декодированным RGB-пикселям и ICC. Source/reference SHA сохранены;
ICC источника перенесён побайтно. Десять scoped проверок прошли; общий pytest:
362passed/3skips, profiles3/schemas8. Пропущены DCC и Windows symlink privilege
проверки, не относящиеся к исполнению ImageMagick. Hosted CI отдельно.

## Ограничения

Это интерполяция в два раза по каждой оси, не восстановление утраченных деталей
и не AI-upscale. Pixel equality относится к воспроизведению исторического метода;
визуальная оценка и точное цветометрическое соответствие исходному объекту отдельно.
ICC/каналы/размеры и повторное чтение файлов проверяются как технические свойства.
Один пакет восьми изображений не доказывает переносимость на другие проекты,
многостраничный TIFF, HDR или CMYK; поддерживаемые ограничения указаны в README.
