# Поток первого примера

1. `dt profiles check` проверяет исходные профили и контрольные суммы.
2. `dt index-pdf` извлекает текст каждой страницы, её полный прямоугольник в PDF
   points и вложенные изображения, сохраняя stable page ID и SHA-256 источника.
   Отсутствие текста отмечается needs_ocr. Наличие текста не означает точный OCR.
3. Реестр и master проходят контракты. Автоматического распознавания материалов,
   окон, размеров, фасадных областей пока нет. Синтетический реестр задан явно.
4. `dt build` создаёт PNG НПМ/ВПМ, размещение UV, снимки job/layout и dev-ZIP.
5. При переданном `--blender` отдельные процессы создают blend и FBX.
6. Валидатор заново читает ZIP, PNG/JSON, а затем FBX в чистом Blender-процессе.
7. Изменения относительно предыдущей сборки сохраняются в `changes.json`.

Ручные ворота будущего реального проекта: sources_confirmed, materials_approved,
master_geometry_approved, facade_and_windows_approved, placement_approved,
collision_review_approved для ВПМ, delivery_approved. Сейчас они не реализованы
как механизм публикации и не считаются пройденными подписью fixture-author.
