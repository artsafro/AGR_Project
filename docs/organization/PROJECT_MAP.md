# Карта AGR_Project

Актуальность: 30.09.2026. Это указатель на файлы и PR, а не свидетельство готовности
реальных ОКС. Репозиторий один: `artsafro/AGR_Project`. Исходные рабочие папки и
игнорируемые результаты DCC остаются локальными. По решению пользователя
29.09.2026 около 4 ГБ `outputs/` не загружать в GitHub.

## Где искать

- `standards/` и `docs/decisions/` — источник норм, страницы PDF и расхождения.
  Три YAML не меняются по пересказу чата.
- `src/dt_ai/` — независимое ядро; `adapters/` — выполнение в Blender, Max,
  Revit и CAD. Доступность адаптера проверяется в текущем сеансе.
- `jobs/<ID>/` — объект, входы, версии и его `STATE.md`. Файлы в `outputs/`
  обычно игнорируются Git и не восстанавливаются из клона.
- `max/AGR_Workbench/` — планируемый перенос собственных инструментов Max.
- `docs/case_studies/` — подтверждённый опыт с точной областью приёмки,
  неудачами и непроверенными пунктами. Новую запись оформлять по
  `docs/EXPERIENCE_CAPTURE.md` и шаблону в этом каталоге.
- `docs/organization/` — карта чатов, процесс извлечения опыта и миграция.
  [Библиотека сценариев](SCRIPT_LIBRARY.md) — проверенные скрипты, запуск и ограничения.
  [Правила обхода](CHAT_LEARNING_LOOP.md), [реестр чатов](CHAT_REGISTER.md)
  и [исходное состояние](CHAT_LEARNING_STATE.json) образуют маршрут работы с опытом.

Перед задачей читать корневой `STATE.md`, затем маршрут `docs/TASK_CONTEXT.md`,
если он уже опубликован, затем состояние конкретного job. Когда маршрута в ветке
ещё нет, искать нужный job/модуль по имени; не считать локальный checkout равным
`main`.

### Локальная проверка вместо обязательного Actions

По согласованию с пользователем 29.09.2026 разбор продолжается без оплаты GitHub
Actions. Для этой очереди успешный облачный CI заменён проверкой конкретного
head-коммита в отдельной чистой локальной копии. Записать SHA базы и head,
команды, результаты, среду и пропущенные проверки в описание PR. Проверить,
что импортируется код этой копии, а не общей рабочей папки. Перед слиянием
снова сверить head и base; при изменении базы проверить совместимость заново.

Обязательны `python -m pytest -q`, `dt profiles check`, `dt schemas --check`
и проверки затронутых рисков. Для документации проверить ссылки и состав diff;
для изменений DCC/экспорта остаются нативные проверки и readback. Ручные ворота
и область пользовательской приёмки сохраняются. PR #18 отложен до нового указания;
после возобновления Max QA остаётся обязательным.

GitHub Actions не считается пройденным: run36595508501 завершился
`startup_failure` до jobs. UI GitHub сообщает о неудачном платеже или лимите
расходов аккаунта; Issue #7 остаётся открытым. Настройки оплаты, защиты веток
и workflow этим решением не меняются. Локальный Windows-прогон не подтверждает
работу Ubuntu runner или установку зависимостей в чистом облачном окружении.
