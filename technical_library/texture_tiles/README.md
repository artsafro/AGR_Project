# Карты материалов: одна операция, конфигурация объекта отдельно

`cli.py` выполняет validate → draw → PNG readback → ZIP readback. `panels.py`
содержит неизменённую панельную математику КПП v001. `kpp_v001.json` — цвета,
размеры и ID/UDIM конкретного кейса; временный clipboard путь не переносится.
Рецепт `solid` общий; `metric_pattern` вызывает уже опубликованный
`tools/facades_texture_pattern.raster`, без второй копии метрической математики.
RGB конфигурации: целые sRGB0–255; raster получает normalized0–1, PNG округляет
к uint8. `extent_m`, offset_m, panel_dimensions_m/joint_m — физические метры,
не произвольное масштабирование по Ground. Реальный metric export этим кейсом
не принят: отдельный synthetic fixture проверяет reuse того же raster.

```powershell
python technical_library/texture_tiles/cli.py --config technical_library/texture_tiles/kpp_v001.json --output <new-directory> --reference <local-original-maps-directory>
```

Output не должен существовать; имена PNG формируются только из целого UDIM.
Duplicate ID/UDIM и неизвестный рецепт отклоняются до создания output.
PNG реально открывается и проверяется; ZIP читается обратно и сверяются SHA.
`opposite_edges_equal` для metric_pattern — диагностическое поле: первый/последний
pixel centre не обязаны совпадать у метрически периодического сигнала.
Исходные карты/сцены не изменяются; ZIP/PNG остаются локально.

[QA.json](QA.json): 11 карт КПП совпали с прежними PNG **по каждому пикселю и
побайтно**. 1001/1005 — 4096², остальные256², RGB. ZIP каждого PNG совпал по SHA.
Алгоритм панели/seed2030 сохранён; 3×8 рисунок не задаёт неизвестный физический
размер панелей. RGB легенды не является лабораторным NCS/RAL преобразованием;
неоднозначный цвет1002 и diffuse-only glass1011 сохранены явно в конфигурации.
`delivery_passed=false`: shader/UV/Max/Checker/визуальная сдача модели не проверены.

Provenance: [SOURCE.json](SOURCE.json). Здесь нет копий v001/v002 каждого объекта;
новый набор карт добавлять данными или новой ответственностью, не вторым builder.


## ДГП v5: замена рисунка из предоставленного атласа

Тот же `cli.py` выбирает `atlas_replace` из `dgp_v5.json`. Модуль `atlas.py`
реализует исходную рабочую операцию `build_brick.py`: RGB → crop нижней половины
2048² атласа → LANCZOS 820×410 → повторение в patch1536×512 → замена прямоугольника
[256,256,1792,768] в diffuse Main006/011/012/013. Координаты — целые пиксели,
правый/нижний край исключён; resize сохраняет пропорции, масштаб820/2048.
Патч повторяется без синтеза цвета и без сглаживания стыков. Это другая операция,
чем генерация метрического рисунка: существующий raster здесь не дублируется.

```powershell
python technical_library/texture_tiles/cli.py --config technical_library/texture_tiles/dgp_v5.json --source <supplied-atlas.png> --maps <v4-textures-directory> --output <fresh-v5-textures-directory> --reference <historical-v5-textures-directory>
```

`--reference` необязателен, но нужен для независимого сравнения с прежним результатом.
Зависимости — Pillow и NumPy (из project/dev окружения). Конфигурация содержит
43 имени и SHA256 входных PNG, хеш/размер атласа, четыре цели и координаты;
локальные пути задаются только аргументами. Для другого кейса создайте проверенную
конфигурацию, а не отключайте проверки ради неподходящих входов. Не используйте
чужие исходники без соответствующих прав.

До создания output сверяются вся PNG-инвентаризация, хеши, цели, crop/границы,
пропорции и RGB целевых карт. Существующий output, вложенный в maps output,
изменённый вход, path traversal и неоднозначные цели отклоняются. После записи
PNG открываются повторно: patch совпадает, каждый пиксель вне прямоугольника
сохранён; 39 остальных PNG копируются побайтно. Хеши входов сверяются снова.
Проверки не зависят от `assert` и работают при Python `-O`. Ошибка после начала
записи может оставить частичный output: он не является принятым результатом;
повторять нужно в новом каталоге. `QA.json` появляется только в конце успешного
прохода. Каталоги и файлы исходников не перезаписываются.

[DGP_QA.json](DGP_QA.json): на фактических v4-входах рефакторинг совпал со
свежим replay исходного скрипта и сохранённым v5 по всем43 PNG побайтно и по
пикселям; четыре карты изменены,39 сохранены. В исходном replay менялись только
привязки путей. Отдельные тесты проверяют отказ до записи при повреждении входов.
Сами атласы, карты, сцены, превью и временные replay-версии в Git не включены.

Около0.25м на кирпич — оценка исходного кейса; сравнения с ВПМ нет.
Бесшовность не доказана (в историческом tile средние RGB-разницы по стыкам
~4.54 и~6.85). Скрипт не меняет сцену Max, material slots, UV или геометрию.
Приёмка визуального вида и актуальная версия Max проверяются отдельно;
`delivery_passed=false` относится к границам этой операции, а не к оценке PNG.

## Read-only Max: текущая версия файла

[Native QA текущего ДГП](DGP_NATIVE_QA.json) сравнивает v4/v5 отдельным Max batch.
Исторический SHA v5 отличается; свежий QA привязан к нынешнему файлу. Только видимость
трёх узлов отличается от v4, помимо четырёх expected diffuse. Причина отличия старых
байтов неизвестна; исправлять видимость этот этап не поручал.

```powershell
$env:AGR_MAX_AUDIT_OUTPUT = '<new local QA path>.json'
& '<Max 2024>/3dsmaxbatch.exe' 'technical_library/texture_tiles/max_readback.py' -sceneFile '<local scene.max>' -safescene on -listenerlog '<new local listener.log>' -log '<new local system.log>'
```

Читает загруженный batch-файл, пишет только новый JSON, не сохраняет сцену. Сравнивает
evaluated triangles/face IDs/smoothing/UV/transforms в native числовом форматировании;
explicit normals, editable polygons, весь shader graph и visual acceptance не проверяет.
Подробный JSON содержит локальные пути bitmap: оставляйте его вне Git, публикуйте
только очищенный итог. Менять sourcefile во время чтения запрещено; обнаруженный drift
останавливает запись результата. Этот helper не правит материалы и не создаёт сцену.
