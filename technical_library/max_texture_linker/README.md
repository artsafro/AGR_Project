# NPM Texture Linker — Standard Legacy

## Контракт

Владелец кода и live Max: root. Задача пользователя от 16.10.2026: один переносимый
`.ms`, drag-and-drop открывает минимальное окно; выбор корневой папки, рекурсивный
поиск T_ текстур, сопоставление по имени объекта, создание нового Standard Legacy
и прямое подключение найденных Bitmap. Поздние уточнения: старые настройки не
сохранять, отсутствующие карты оставлять пустыми. Финальное уточнение: каждому
glass mesh отдельный M_Glass_01/02/... по возрастанию имени, карты убрать, opacity 50,
остальные параметры скопировать. Добавить упрощённый FBX → JSON → export из Завода.
Разрешены скрипты, инструкция, проверки и краткая навигация/STATE. Существующая
пользовательская сцена — только чтение до самостоятельного запуска пользователем.
Нормы, геометрия, UV, исходные файлы и другие инструменты не изменяются.

План: автономное ядро анализа/подготовки материалов → UI → native проверки
в отдельной синтетической batch-сцене → независимое review → передача.
При ошибке обхода папок остановиться до назначения; неоднозначный набор пропустить.
Проверки: native MAXScript, отрицательные случаи, повторный запуск, project QA.
Проверка пользовательского drag-and-drop и визуальная приёмка остаются ручными.

## Использование

Перетащите `NPM_Texture_Linker.ms` в viewport 3ds Max. Выберите папку сохранения
и папку текстур, затем нажмите «Подключить текстуры и M_Glass».
Обрабатываются все геометрические объекты сцены, включая скрытые; выделение не нужно.
Результат выводится в окне, подробности — в MAXScript Listener (F11).
Изменения назначений объединены в один Undo. Скрипт не сохраняет сцену.

Имя `SM_<ключ>` или `<ключ>` сопоставляется **целиком**, без учёта регистра, с
`T_<ключ>_<канал>_<номер>.<расширение>`. Например:
`SM_77_17_0120316_33510_001_Main` → `T_77_17_0120316_33510_001_Main_d_1.png`.
Номер сохраняется в имени файла; несколько номеров/копий/расширений одного канала
считаются неоднозначностью: весь объект пропускается. Поддержаны PNG/JPG/JPEG/TIF/
TIFF/TGA/BMP/EXR/DDS. Каталоги junction/symlink не обходятся.

Каналы: d → Diffuse, r → Glossiness, m → Reflection, o → Opacity, n → Bump.
Все — обычный Bitmap напрямую, Texture / Explicit Map Channel 1. Roughness
не инвертируется; Normal Bump не создаётся. Имена нод — имена файлов без расширения.
Это запрошенная схема обмена. Значения Bitmap Output не инвертируются.

На каждый найденный ключ создаётся **новый** `M_<ключ>_1`, даже при наличии
назначенного материала другого типа. Несколько объектов одного ключа используют
один новый экземпляр. Отсутствующие каналы пустые, старые настройки не переносятся.
Нет ни одной подходящей карты — объект не меняется.

Старые материалы с совпадающим новым именем заменяются во всех их ссылках
(сцена, submaterial, Compact/Slate Editor) через `replaceInstances`. Область
замены задаётся точным именем материала без учёта регистра. Внешние библиотеки на
диске не изменяются. Старые материалы с другими именами снимаются с ОКС, но
их независимые назначения/редакторские ссылки не очищаются.

Исключение: имена `M_Glass*`, `M Glass*`, `MGlass*` без учёта регистра. Для каждого
mesh создаётся отдельная копия стекла, все её texture-map слоты отключаются,
opacity становится 50; остальные параметры сохраняются. Нумерация `M_Glass_01`,
`02`, ... начинается заново по естественному порядку полных имён mesh (2 раньше 10).
Вложенное в Multi/Sub стекло также копируется и нумеруется, остальные submaterials
сохраняются. Старые редакторские ссылки стекла заменяются первой соответствующей
новой копией. Стекло без свойства opacity останавливает операцию
до изменений с явной ошибкой (поддержан непосредственный opacity, не renderer-specific
эквивалент прозрачности).

Повторный запуск заново создаёт материалы и заменяет прежние одноимённые ссылки.
Текстуры на диске не изменяются. Один Undo охватывает назначения, замены и стекло.
Скрипт не очищает Undo: предыдущие материалы остаются доступны для отмены операции.

Native fixture: `3dsmaxbatch.exe test_native.ms -mxsString fixture:yes`.
Тест создаёт только синтетическую сцену в новом batch-процессе, файлы/логи в
`tmp/max-texture-linker-native/`. В пользовательской сцене fixture запускать нельзя.

API: [Autodesk replaceInstances](https://help.autodesk.com/cloudhelp/2015/ENU/MAXScript-Help/files/GUID-95453E22-A022-4543-B31C-A052CECD3598.htm),
[Slate API](https://help.autodesk.com/cloudhelp/2024/ENU/MAXScript-Help/files/3ds-Max-Objects-and-Interfaces/Interfaces/Core-Interfaces/Core-Interfaces-Documentation/S/GUID-7E144C67-4F97-4A2A-924E-711870C7DF6E.html).

## FBX → JSON → экспорт

1. Выберите папку **исходных FBX**, нажмите «Анализ подпапок → новый JSON».
   Файлы рекурсивно читаются с диска без импорта. В папке сохранения создаётся
   новая `NPM_FBX_<timestamp>` и в ней `npm_fbx_inventory_<timestamp>.json`:
   источник/sha256/относительный путь и точные имена Mesh каждого FBX.
2. Или нажмите «Есть JSON — выбрать и проверить»: валидный JSON этого инструмента
   копируется в новую папку результата. Legacy JSON Завода требует нового анализа.
3. Только после проверки исходников и наличия всех mesh в сцене активируется
   «Экспорт FBX по проверенному JSON». FBX сохраняются **рядом с JSON** в той же
   новой папке, с исходной структурой относительных имён. После экспорта кнопка
   отключается; повторный экспорт требует новой папки/проверенного JSON.

Отбор НПМ ограничен проверяемыми данными контейнера и naming из
`standards/NPM_STANDARD.yaml` (страницы источника 10–13): binary FBX7400;
`4цифры_Address_01..20.fbx` / `_Ground.fbx`; все Mesh соответствуют тому же Address
и `SM_Address_001..020_Main` / `MainGlass`, либо `SM_Address_Ground` для Ground.
Посторонние/нечитаемые FBX записываются в JSON `skipped` с причиной. Поля
`full_npm_verified=false` и `npm_candidate` **не подтверждают** triangle budget,
UV, материалы, координаты и прочие требования НПМ. Если кандидатов нет — ошибка.

Нужен встроенный Python 3ds Max (проверяется на Max 2024); системный Python,
FBX SDK и сторонние модули не требуются. Пользователю нужен **только `.ms`**:
`fbx_inventory.py` встроен в него. Для разработчика исходник reader и
`embed_fbx.py` сохранены рядом; после изменения Python выполнить `python embed_fbx.py`.

Схема source JSON версии 1 проверяет исходные SHA перед экспортом. Неполные или
дублирующиеся scene names останавливают весь экспорт до записи FBX. Источник
не перезаписывается, предыдущие выходы не удаляются. При ошибке частичные новые
файлы сохраняются с сообщением, но не объявляются проверенными. Выходные каталоги
`NPM_FBX_*` исключаются из последующего анализа.

Экспорт использует временные копии: на них убираются custom attributes узлов,
baseObject, модификаторов, материалов и карт, а также User Properties. Оригинальные
геометрия, UV, материалы, CA и User Properties остаются в сцене. Selection и
FBX settings восстанавливаются; копии отменяются через отдельную hold-транзакцию.
Не выполняются Reset XForm, Weld, collapse или переименование UV.

Профиль по исходному Завод workflow: binary FBX2014, Y-up, метры, scale 1,
triangulate, smoothing groups, embed textures; без animation/lights/cameras.
`export_report.json` фиксирует SHA и проверяет точный состав Mesh каждого выхода.
Его `verified` относится **только к mesh membership**; это не полная проверка
геометрии/UV/материалов или сдача AGR. Источник алгоритма:
`Desktop/zavod/scripts/fbx/{inspect_fbx.py,export_fbx_inventory.ms}`;
исходные скрипты Завода не изменялись.
