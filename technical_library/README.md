# Техническая библиотека AGR

Библиотека хранит компактные рабочие пакеты по операциям, а не каждый временный
скрипт из чата. Перед задачей выбирайте операцию и прочитайте её область проверки.
Новый объект получает конфигурацию/данные; новый Python-файл нужен только для
новой ответственности, которую нельзя добавить в существующий пакет.

## Исполняемые пакеты

- [UV стен v006](UV_V006.md): четыре этапа `inventory → solve → build → verify`,
  один общий модуль состояния/запуска. Десять исторических операций объединены;
  прежние скрипты в этот пакет не копируются. Один проверенный объект СОШ1150.
- [Box lights, PR #25](https://github.com/artsafro/AGR_Project/pull/25): четыре
  этапа инспекции/анализа/построения/QA, с README и native Blender replay.
  Пакет остаётся отдельным draft до слияния.
- Connect, Exterior, Shell и периодический рисунок фасадов — существующие
  модули `src/dt_ai/` с адаптерами и тестами в main. Переиспользовать их;
  исторические прототипы не должны создавать вторую реализацию той же операции.
- [Workbench, PR #18](https://github.com/artsafro/AGR_Project/pull/18) — собственный
  Max-пакет уже сохранён отдельно; его ревью/QA отложены пользователем.

## Правило пополнения

1. Из этапов успешной задачи выделить ответственности, входы/выходы и проверки.
2. Найти существующую реализацию и определить, что является новым алгоритмом,
   параметром конкретного объекта или временной диагностикой.
3. Обновить существующий модуль либо создать небольшой пакет с понятными этапами.
   Общую логику вынести в функции; параметры/ID/пути оставить в конфигурации.
4. Сравнить результаты исходного маршрута и рефакторинга на тех же входах.
   Добавить README, небольшой QA-отчёт, связь с кейсом и ограничения.
5. Черновые версии и дубли остаются локально. Ошибку сохранять как вывод с
   контрпримером/проверкой, а не десятки копий неудачного кода.

Четыре этапа — модель этого UV-кейса, не обязательное число для всех задач.
Главный критерий — одна реализация операции и воспроизводимый результат.
Нельзя объявлять общий Skill по одному объекту; переносимость проверяется отдельно.
