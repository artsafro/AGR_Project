# GLB A/B Main: реконструкция атласа по захваченным UV

Один Python renderer и одна конфигурация для двух корпусов одного проекта.
Здесь хранится проверенная сборка RGBA PNG, а не универсальная UV-автосборка.
Локальные исходники, текстуры, PNG и MAX в пакет не входят.

## Входы и запуск

Python 3.10+ и Pillow. Версия реально использованного Pillow указана в `QA.json`.
CSV берутся из read-only захвата **исходных UV до remap**:
`uv_before.csv` содержит `id,u,v`; `face_uv_before.csv` содержит
`id,u0,v0,u1,v1` и одну строку на грань. Дополнительные столбцы допускаются.
Каталог текстур должен содержать три карты из `scenarios.json`.
Пути пользователь передаёт явно; их не сохраняют в манифест.

```powershell
python -m pip install Pillow
python technical_library/glb_atlas/build.py --node A_Main --input jobs/A-MAIN-ATLAS/outputs/v001 --textures jobs/GLB-NPM/outputs/source-live-v001/textures --output jobs/A-MAIN-ATLAS/outputs/replay-new
python technical_library/glb_atlas/build.py --node B_Main --input jobs/B-MAIN-ATLAS/outputs/v001 --textures jobs/GLB-NPM/outputs/source-live-v001/textures --output jobs/B-MAIN-ATLAS/outputs/replay-new
```

Выходной каталог должен отсутствовать: повторный запуск не перезапишет принятые
данные. Скрипт проверяет число граней, известные ID и конечность UV. Результат:
`<node>_1001_2048_RGBA.png` и `atlas_manifest.json`. Статус манифеста остаётся
`TRIAL / QA NOT PASSED`: сборка PNG не означает приёмку модели.

## Алгоритм и единицы

2048² пикселей, отступ 8 px, UV безразмерные. Фиксированные участки отделок
заданы в конфигурации; координаты PNG Y растут вниз, UV V — вверх. Текстуры
кропятся по принятому рецепту, затем центральным crop под пропорции участка и
LANCZOS resize. Внутренняя часть бетона исключает исходные видимые швы.
Окна и alpha-перфорация AC реконструируются по округлённым до 4 знаков
UV bounding boxes граней. Стекло RGB(255,255,255), alpha 255. Пороговые
условия фронтов AC относятся только к этому захвату. Раздельные UV-группы
колонн и стемалита сохраняются в манифесте для будущего адаптера.

`window_atlas` рисует окна по размерам створок и DOCX-картам; `texture_tiles`
синтезирует периодические панели. Их алгоритмы не используют этот захват
UV-граней и изменили бы принятые пиксели. Поэтому сохранён один компактный
сценарий A/B; параллельные версии для корпусов не создаются.

## Что проверено и что ещё не перенесено

02.10.2026 повторная сборка на тех же четырёх CSV и трёх текстурах совпала
по всем RGBA-пикселям **и PNG-байтам** с A v001 и B v002 (белое стекло).
Хеши входов и PNG приведены в `QA.json`; исходники и принятые PNG не менялись.
Проверены запрет перезаписи и отклонение NaN. Это локальная проверка,
не GitHub Actions и не новый Max readback.

MAXScript-адаптер **пока не опубликован**. Исторический генератор содержит
персональные пути и изменяет сцену; параметризованный локальный кандидат
не имеет нового native `fileIn`/сохранения/повторного открытия. Следующий шаг:
проверить адаптер на отдельной копии исходной MAX с точной идентичностью
сцены, ID/UV и запретом перезаписи, затем сопоставить UV/ID с прежним маршрутом
и только после этого добавить его в пакет. Исторические скрипты остаются
локальными — перенос PNG-логики не закрывает перенос UV-операции.

A v001 PNG не воспроизводит последующий перенос 44 граней ID5 в ID13 и
неизвестные правки сцены v005. Этот перенос остаётся отдельно описанным в
кейсе A Main; UV и модель v005 здесь не проверены. FBX round-trip, alpha
после экспорта, AGR Checker и полная производственная сдача не проведены.
Два корпуса одного проекта не доказывают универсальность на втором проекте.
