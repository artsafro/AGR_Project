# AGR Workbench 0.5 — инструменты НПМ и ВПМ

Запуск: распакуйте папку целиком. В 3ds Max выберите Scripting → Run Script →
AGR_Workbench.ms. Проверено в Max 2024. Исходные сторонние окна не запускаются.

## Как пользоваться

1. Выберите вкладку НПМ или ВПМ.
2. Выделите нужный объект в сцене Max. Его имя появится над инструментами.
3. Слева нажмите нужный инструмент. Справа показаны только его параметры:
   зачем он нужен, что выделить и что получится.
4. Если доступна кнопка «Проверить без изменений», сначала прочитайте результат.
   Затем нажмите кнопку конкретного действия.

Сохранённых наборов больше нет. Каждое нажатие работает с текущим выделением
Max. Смена выделения сразу меняет область действия. Для полигональных операций
по умолчанию нужны выбранные полигоны; обработка всего объекта включается явно.
Если кнопка неактивна, проверьте строку выделения вверху и условия в описании.

## НПМ здания: размер рисунка, а не плотность Ground

На здании необходимо сохранить физический размер кирпича, плитки и рисунка
отделки относительно утверждённой ВПМ. Плотность Ground к НПМ ОКС не применяется.
Разрешение атласа влияет на резкость, но не должно само менять размер кирпича.
Инструмент «Размер рисунка · UV-проекция» задаёт сторону всей квадратной текстуры
в метрах: при значении 2 её полный рисунок занимает участок 2×2 м.
Это начальная плоская проекция; она не строит атлас и может выходить за 0–1.
Для сложных фасадов с разными отделками нужна отдельная раскладка по областям.
Существующая UV1 обязательна, чтобы не обнулить развёртку остальных полигонов.

«Ground · плотность (диагностика)» предназначена только для поверхности рельефа.
Требуется явное подтверждение области; объекты с ролью Main/MainGlass/UCX
отклоняются. Сейчас измерение выдаёт px/м и НЕ проверяет норматив Ground
в px/м². Нормативный PASS не выдаётся. Для ВПМ измерение px/м доступно отдельно.

## Доступные инструменты

- Имена для сдачи: задайте SM_Address, роль и номер. Предпросмотр показывает
  будущее имя; применение меняет имя и служебную роль. Один объект на Main,
  MainGlass или Ground; несколько допустимы для нумерации UCX. Attach не выполняется.
- Размер рисунка: UV-проекция выбранных плоских полигонов Editable Poly по XY,
  XZ или YZ. Физический масштаб и общая фаза относительно мирового нуля сохраняются.
  Наклонённые к плоскости грани отклоняются, чтобы избежать растяжения.
- Перенос готовых UV: перевод всей развёртки размером до 1×1 в центр тайла.
  НПМ — 1001, ВПМ — выбранный UDIM. Масштаб сохраняется, упаковки нет.
- Плотность: диагностическое измерение для указанного разрешения квадратной карты.
  Смешанные разрешения, корректность отделок и padding не подтверждаются.
- UV одной отделки → UDIM (ВПМ): укажите Material ID полигонов и целевой тайл.
  Перенос сохраняет масштаб и не сдвигает UV других ID, даже при общих вершинах.
  UV должны помещаться в один тайл. Инструмент не упаковывает острова и не
  проверяет, занят ли тайл. Material ID не обязан совпадать с номером UDIM.
- Выпуклая оболочка (ВПМ): выберите объёмный участок Editable Poly, задайте лимит
  вершин. Создаётся отдельная коллизия по форме; исходник сохраняется. Оболочка
  закрывает проёмы и вогнутости, поэтому сложное здание обрабатывайте частями.
  Плоские участки отклоняются. После создания назначьте имя UCX.
- Файлы текстур: список существующих и потерянных ссылок в материалах выделения.
  Пути не меняются. Последовательности/UDIM-токены требуют отдельной проверки.
- Connect: соединение выбранных рёбер Editable Poly с заданным числом сегментов.
  Проверяйте результат на квады и сохранность проёмов.
- Коллизия-бокс (ВПМ): новый объём по мировым осям вокруг выбранных полигонов.
  Требуется объёмный участок. Бокс закрывает проёмы; это не точная оболочка.
  Результат выделяется — назначьте ему UCX через инструмент имён.
- Свет по полигонам (ВПМ): выберите Editable Poly и FreeSpot-образец кнопкой.
  Создаётся независимый источник в центре каждого полигона по наружной нормали.
- Проверка перед экспортом: имена, роли, материалы, UV, потерянные карты.
  Это частичная диагностика, не AGR Checker.
- Экспорт: выделите все объекты данного FBX. После проверки открываются штатные
  настройки FBX Max; существующий файл не перезаписывается.
- Проверить FBX: укажите сохранённый файл. Отдельный Blender проверит его чтение,
  меши, размеры, UV и материалы, сохранив JSON рядом. Сцена Max не меняется.

## Зачем отдельная версия

Только если нужно сохранить исходную модель перед обработкой: выделите меши
и выберите «Создать отдельную версию». Появятся дубликаты геометрии и материалов
на том же месте. Новая версия автоматически выделяется — дальше работайте с ней.
Исходные объекты остаются видимыми. Файлы текстур не копируются.
Это необязательная операция, а не условие работы остальных инструментов.
Прямое изменение инстансов блокируется: используйте отдельную версию,
чтобы не изменить связанную геометрию вне выделения.
Изменения сцены объединяются в Undo; файловые операции обычным Undo не отменяются.

## Ещё переносим

Отдельный видимый список показывает незавершённые модули: камеры и сборку
фасадного атласа, растительность, рельеф/покрытия, трубы, проёмы, запекание,
упаковку отделок, декомпозицию коллизий/сечения, оптимизацию света, повтор операций,
импорт GeoJSON. Эти пункты объясняют статус и не открывают старые окна.
Простая UV-проекция не является полной заменой Facade Atlas или Maf Tools.
Полный перенос всех функций исходных скриптов ещё не завершён.

## Проверки

test_tasks.ms: синтетические проекция/масштаб/защита от растяжения,
бокс/границы/отказ плоского участка, свет/направление/независимость, Connect.
test_ui_selection.ms: живое выделение, смена объекта, предпросмотр без изменений
геометрии и метаданных, прямое применение UV, ограничение Ground, дубликаты,
переключение обеих вкладок и события меню.
test_pipeline.ms: имена, конфликты, карты, UV-тайл, экспорт синтетического FBX.
test_extensions.ms: перенос UV по ID без изменения масштаба и соседних ID,
отказ слишком больших UV, построение/экспорт выпуклой оболочки, сохранность
исходника, отказ плоских участков, потерянная карта.
Собственные тестовые объекты удаляются, пользовательская сцена не сохраняется.
test_core.ms запускается исключительно в пустой тестовой сессии.
Вёрстка НПМ и новой панели ВПМ визуально просмотрена на реальных скриншотах Max.

Нет полной проверки топологии, внешнего вида, коллизий/зазоров, групп отделки,
GeoJSON и AGR Checker. delivery_passed остаётся false. Context7 недоступен;
поведение проверялось фактическим исполнением в Max и локальными источниками.
Исходные папки пользователя не изменены. Использованы и переосмыслены подходы
из apply_atlas_uv.ms, UCX_Tools.ms, FreeSpot_Tools.ms и edge_connect_segments.ms;
их старые интерфейсы не включены в запуск.
