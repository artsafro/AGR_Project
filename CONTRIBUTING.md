# Участие в проекте

1. Начните с `STATE.md`, затем выберите маршрут в `docs/TASK_CONTEXT.md`.
2. Создайте узкую ветку от актуального `main`; одна операция или один риск на PR.
3. Не добавляйте `jobs/*/outputs`, рабочие `.blend/.fbx`, данные заказчика,
   секреты и сторонний код без подтверждённого права использования.
4. Для спорной нормы укажите страницу PDF и решение в `docs/decisions/`.
5. Выполните `python -m pytest -q`, `dt profiles check`, `dt schemas --check` и
   проверки затронутого DCC-риска. Локальный QA не называйте GitHub Actions.
6. В PR разделите реализацию, техническую проверку, пользовательскую приёмку и
   публикацию. Не ставьте `delivery_passed=true`, пока открыты обязательные ворота.

PR #18 и Workbench остаются отложенными до отдельного указания владельца.
